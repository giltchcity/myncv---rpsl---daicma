## The goal, in the user's words

Whatever the current session can already do well must not get noticeably worse
because of memory; and memory must add correct extra coverage and a more correct
query-time state. Concretely, all four at once:

* current reconstruction >= Clean;
* query-time stale geometry < Khronos;
* valid persistent coverage clearly > Clean;
* A -> B -> C recursion holds.

Formally (notes §4): `P_k = Update(P_{k-1}, O_k, T_k)` with (i) **no-regret** --
in the observed domain CURRENT(P_k) no worse than from-scratch(O_k); (ii)
**monotone information gain** -- persistent/historical information strictly more
than from-scratch; (iii) **bounded storage** -- state size scales with scene
content, not with time.

Retirement rules, the TSDF prior, archive-boundary free space and deformation
correction are **candidate mechanisms** serving this goal. A mechanism may die;
the goal does not change. Do not redefine the project as "prove the newest
mechanism is right".

## Four systems. Clean is the control, not Khronos.

1. **Official Khronos** -- A/B/C each run independently, no cross-session memory.
   External baseline.
2. **Clean** -- our full method code, each session from an empty map. This is the
   causal control for "did memory damage the current reconstruction".
3. **Memory** -- A->B and A->B->C. The actual recursive persistent mapping.
4. **Memory + TSDF prior** -- branch `memory-tsdf-prior`.

The quantities that matter are **Memory - Clean** and **(Memory+Prior) - Memory**.
Never summarise as "synthetic good / real bad".

## The F-score protocol. It is NOT a two-mesh F-score.

`tools/abc_eval_v2/geometry_score.py`:

* reference `<session>_reference_2cm.ply`; the ABC comparison table deliberately
  substitutes `_reference_1cm.ply` (see `score_stage.py`);
* both sides sampled as dense area samples reduced to a **fixed-origin 2 cm voxel
  union**, one vote per occupied surface voxel, which removes object/background
  overlap multiplicity;
* distances are **exact closest-triangle** (Open3D RaycastingScene), both ways;
* **the primary metric is the observed domain only**: `dp[pe>=3]`, `dr[re>=3]`. A
  point qualifies when >= 3 of the 2 Hz depth frames place it in free space or
  within 0.1 m of the measured surface. **Person and non-final cabinet are masked
  out of the raw depth.** Occluded-only and unobserved points are excluded and
  coverage is reported separately;
* **no prediction-distance or GT-distance spatial crop**;
* the unfiltered two-mesh number is `unfiltered_diagnostic`, not the headline;
* also emitted: domain sensitivity at >=1/>=3/>=5, depth-evidence diagnostics,
  and sha256 provenance for source, prediction, reference and domain.

Sampling is density based (one sample per 5 mm^2 before the voxel union), so a
larger map is not sampled more sparsely. A recall change is a real coverage
change, never a sampling artefact.

### The property that must never be forgotten

Fixed reference, fixed evaluation points: if geometry is only **added** and
nothing is deleted or moved, `M1 subset M2 => d(y,M2) <= d(y,M1)`, so **recall
cannot decrease**. Therefore:

* a **precision** loss may be argued about with the reference (it can charge
  correct-but-unobserved memory as error);
* a **recall** loss may never be. It is proof of deletion, displacement, or
  failed reconstruction, and it is ours.

## The unresolved question (state it this way)

Why does recursive memory fail to provide positive transfer over the same
pipeline without memory, and why did the TSDF-prior mechanism not materially
change that on real data while synthetic benefits strongly?

What is known about the second half: the prior was a **precision** fix that also
**cut transfer**. Recall transfer over Clean fell from +0.49/+0.68 pp (B/C) to
+0.18/+0.31 pp while precision cost fell from -0.88 pp to -0.19 pp at B. Net F1
flat. By the monotonicity rule, the recall fall cannot be a reference artefact:
`Backend::replaceInheritedInArchivedBlocks` **erases** inherited vertices once a
seeded block is archived, so the re-integrated TSDF surface is not reproducing
everything the frozen mesh covered. The same branch already measured **13.78%
missing surface** against V37 on synthetic alongside 12.17% phantom. Missing
surface is the recall loss; the two datasets were reporting one defect.

The coverage guard in that function claims "replacement can never lose coverage"
because it requires a session vertex within one voxel. That contract is being
violated -- it checks vertex proximity, not that reference-covering surface
survived. Definite location, not a hypothesis.

Not yet distinguished, and must be: prior not dominating the final map;
downstream re-adding old mesh; improving a region that is not the bottleneck;
hypothesis insufficient.

## Two distinct defects of the real reference. Only the first is addressed.

1. **Time-union rewards stale geometry.** The pseudo-GT is rebuilt from every
   depth frame of the session, so it contains objects that moved *during* the
   session. Measured from sensor data alone (last free ray later than last
   supporting ray, >=3 free): 2.96% of the gated stage-B reference. Retention of
   it: Khronos 92.6%, Clean 59.5%, Memory+Prior 63.2%. This accounts for 0.98 pp
   of the 1.42 pp apparent recall gap to Khronos.
2. **A B-only reference cannot reward valid unobserved memory.** A wall A saw, B
   never saw, that really was there in B, is simply absent from the reference.
   Memory+Prior has 2.1 m2 of such surface, 90.8% never exposed by any B ray,
   only 7.4% ray-contradicted. **No metric exists for this.** This is where
   positive transfer actually lives on real data.

## Dead hypotheses. Do not redo these.

* `active_window.mesh_integrator.min_weight` 5 -> 0.0001 (upstream default):
  +0.11 pp recall, -0.15 pp precision, F1 slightly worse.
* Turning off background change detection entirely: +0.23 pp recall, costs
  precision, F1 +0.03 pp. Our deletion is 12.9x enriched on genuinely-vanished
  surface, so it is not the false-removal failure Khronos attacks Panoptic for.
* Active-window block seams (0.8 m lattice): flat, ratio 1.19 in the nearest bin.
* Object layer: 94.2% of the surface we miss is covered by Khronos's *background*
  layer; our background and theirs have the same face count (196320 vs 196315).
* Instrumentation probes changing backend cadence (the "0.12 pp regression").
* Out-of-room geometry: 73% wrong but only 0.1% of scored FP mass.
* Room crop must be oriented to the room (44.5 deg); +1.8 pp, ranking unchanged.
* Union / persistent references: a naive union rewards stale object poses.
* Deleting inherited surface occluded by its replacement: +0.13 pp, weakens the
  retention principle. **`fefef86` is in this family and should be reverted.**

Still unexplained: 0.45 pp of recall on genuinely persisting real surface.

## Novelty framing. Do not shrink the ambition.

Three layers, kept separate:

1. **Problem/idea**: recursive persistent 4D mapping where every independent
   session handles D1/D2/D3 and the map expresses query-time world state rather
   than a union of historical observations.
2. **Algorithm**: what computation lets a *deformable* persistent memory become a
   query-time estimator again on revisit. This layer is what the method section
   needs and is currently missing.
3. **Primitives**: TSDF, PGMO, active window, ray evidence, mesh, marching cubes,
   GTSAM, nearest-neighbour. Borrowed on purpose. Khronos internals may be
   modified.

A prior-art search exists **only** to stop us claiming a primitive is new. It
does not decide how ambitious the paper may be. Known primitive disclosures:
US9972137B2 (Eonite/Intel) *Selective-Remapping* and *Map Priors*; InfiniTAM
block swapping with secondary fusion on restore; US11992950B2 (KAIST) rebuilding
a volumetric map from deformed surfels. Full report with 212 quoted passages:
`scratchpad/lit/PRIOR_ART.md` (session-local; copy it out if it matters).
