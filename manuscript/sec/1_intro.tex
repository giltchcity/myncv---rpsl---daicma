\section{Introduction}
\label{sec:intro}

\textbf{The world does not reset when the mapper does.}
Robots are deployed episodically: they stop, recharge, restart, and later return
to environments that have continued to evolve in their absence. Yet robotic
mapping largely inherits the opposite computational assumption. A dynamic mapper
may build rich spatio-temporal understanding while a deployment is active, but
once that session terminates, a later deployment typically inherits a map
representation---static, current, or object-level---rather than the temporal
scene understanding that produced it. The geometry may persist; the dynamic
reasoning does not.

This exposes a separation between two mature lines of research. Dynamic mapping
and SLAM increasingly reason about \emph{how} a scene changes while a mapping
process remains active: moving entities can be tracked through time, and changes
revealed after temporary observation gaps can be reconciled against previous
scene state~\cite{runz2017cofusion,xu2019midfusion,morris2025dynosam,schmid2024khronos}.
Lifelong and multi-session mapping address the complementary problem of carrying
information across revisits, but typically preserve an updated current map, a
static localization map, or selected persistent landmarks rather than the full
temporal scene understanding that existed during the previous
deployment~\cite{kim2022ltmapper,gil2025elite,ali2026probperlilo,schmid2022panoptic}.
In short, dynamic mapping preserves temporal understanding within a session,
whereas lifelong mapping preserves maps across sessions. What is missing is
\emph{persistent mapping}: carrying enough scene-level state across deployments
for the same dynamic reasoning to recur.

This separation is artificial from the perspective of the physical world. A
session boundary is caused by robot operation, not by an environmental reset. If
an object moves while the robot is watching, that observed motion remains part
of the world's history after the robot shuts down. If another element changes
while a region is temporarily outside the field of view, the uncertainty about
that transition likewise does not disappear merely because the mapping process
is restarted. Collapsing such knowledge into a single current-map snapshot
therefore creates a temporal information bottleneck exactly where the robot
changes deployments. This motivates a simple question: \emph{why should a
returning robot inherit only a map snapshot rather than the scene understanding
accumulated before it left?}

Our key observation is that independently executed mapping sessions are more
naturally viewed as interrupted observations of one continuously evolving world.
We therefore treat a session boundary as an interruption of dynamic mapping,
rather than a reset of the mapping problem. This view exposes a hierarchy of
observability. Within a running session, an entity may change while its
transition is directly observed (\emph{D1}), allowing the system to retain an
actual trajectory and time-indexed geometry. Alternatively, the scene may change
while the robot looks elsewhere (\emph{D2}); only the states before and after the
observation gap are available, requiring reasoning about persistence, absence,
lack of observation, and newly supported content. Across deployments, the
observation gap becomes global: the complete mapping process is absent while the
world continues to change. We call this inter-session evolution \emph{D3}. Put
differently, D2 asks what changed while the robot looked away; D3 asks what
changed while the robot itself was away.

Crucially, D3 is not a third change detector running alongside D1 and D2. It is
the persistent interface connecting complete dynamic-mapping sessions. Session A
executes D1 and D2, exports sufficient scene state, and terminates. An
independently initialized Session B then imports this state, reconciles the
changes that occurred during the inter-session gap, and again executes its own
D1 and D2 events before exporting the prior for Session C. The output of a
session is therefore no longer merely a map; it is the prior state of the next
dynamic-mapping session.

Recent scene-memory systems make the remaining gap especially clear. Persistent
3D memories can recognize a previously visited environment, relocalize against
stored geometry, and refine a recalled static scene~\cite{wang2026cognimap3d}.
Object-centric Gaussian maps can maintain persistent instances, relocalize later
observations against an existing representation, and revise removed or newly
observed objects~\cite{ge2026dgsgmind}. These are important advances in persistent
scene representation, but they do not preserve the complete spatio-temporal
mapping capability of a deployment: the former intentionally stores static
landmarks in persistent memory, while the latter does not include an integrated
dynamic tracking module. Conversely, dense spatio-temporal systems such as
Khronos preserve substantially richer dynamic history within one running
session~\cite{schmid2024khronos}, but do not define the persistent session-state
interface above. We target precisely this missing connection: a shift from
persistent maps to persistent mapping.

We formulate the resulting problem as \emph{Persistent Spatio-Temporal
Metric-Semantic Mapping} (P-SMS): independent robot deployments are treated as
successive episodes of one persistent dynamic scene memory. We instantiate this
principle by extending dense single-session spatio-temporal mapping with a
persistent scene-state interface and conservative inter-session reconciliation.
A completed session exports current metric-semantic geometry together with object
and structural state, change evidence, temporal scene information, and session
provenance. A later independent session uses this state as a prior, retains
inherited content that has not been sufficiently re-observed, removes old content
only when contradicted by reliable current evidence, incorporates newly supported
geometry, and concurrently runs within-session dynamic mapping. The design goal
is not a native hot restart of every live backend data structure, but persistence
of the scene-level state required for dynamic mapping to recur across deployments.

Our contributions are:
\begin{itemize}
    \item We formulate \emph{persistent dynamic mapping}, in which observed
    dynamics (D1) and hidden changes (D2) are modeled within every deployment,
    while inter-session evolution (D3) connects independently executed sessions
    through persistent scene state.

    \item We introduce a persistent scene-memory and evidence-gated
    reconciliation framework that carries dense current geometry, object and
    structural state, temporal scene information, observability/change evidence,
    and session provenance across deployment boundaries without equating
    non-observation with absence.

    \item We define a recursive evaluation protocol in which a completed session
    initializes a later independent deployment, which must reconcile D3 while
    again processing new D1 and D2 events and producing the scene state for
    subsequent deployments.
\end{itemize}
