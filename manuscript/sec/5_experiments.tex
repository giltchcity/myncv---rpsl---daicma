\section{Experiments}
\label{sec:experiments}

We attach the same update layer to a TSDF, a 3D Gaussian, and an occupancy mapper and ask whether obsolete states
leave the map, whether the map stays as accurate as a map of the current run alone, whether the memory of earlier runs makes
it more complete, and whether each run still maps its own changes. Each
mapper also runs without our layer, from an empty map and with its own update where it has one.

\subsection{Setup}
\label{sec:setup}

\paragraph{Datasets.}
\emph{Real room.} We record one room three times with a Kinect: run A (133\,s, 4{,}003 frames), run B (135\,s,
4{,}041 frames) about six hours later, and run C (241\,s, 7{,}216 frames) twelve days after B. B starts from A's
exported state and C from B's, and rigid transforms align B and C with A. The room holds 20 objects. Between A and B,
seven moved objects, one addition, and one removal give 16 appearance or disappearance events. Between B and C, four
moved objects and two removals give 10 events. One cabinet changes out of view once in A, twice in B, and twice in C.
Object reference surfaces come from RGB-D measurements aggregated over annotated presence intervals.

\emph{Simulated apartment.} Two Isaac Sim runs observe one furnished apartment: A with 4{,}186 frames and B with
3{,}555 frames at 30\,Hz, with exact poses, semantics, and instance labels. B starts from A's final state and
observes only part of what A mapped. The complete scene mesh is the reference inside and outside the current camera
coverage.
\emph{Flat.} The public Flat dataset~\cite{schmid2022panoptic}, which Panoptic Multi-TSDFs, GaME, and wavemap also use,
has two simulated runs of one flat with 400 and 362 frames, exact poses, and instance labels. Between the runs, eight
objects move, seven appear, and four disappear. A point reference of each run's scene comes with the data.

\paragraph{Compared methods.}
We compare against published methods on the same recordings: Khronos~\cite{schmid2024khronos}, which maps each run
with dynamic and change reasoning but starts every run from an empty map; Panoptic Multi-TSDFs~\cite{schmid2022panoptic},
which keeps object submaps that become persistent, absent, or unobserved across visits; GaME~\cite{yugay2026game},
which updates a Gaussian map after changes out of view; and wavemap~\cite{reijgwart2023wavemap}, whose log-odds update
clears the cells that rays traverse. We run our layer on three backends: a Khronos TSDF pipeline, GaME, and wavemap.
Each backend keeps its code, inputs, and resolution, so the difference to its published counterpart is our layer.

\paragraph{Metrics.}
\emph{Online object F1} evaluates the map of every moment against the objects present at that moment, weighted by the
duration of each state, with the object evaluator of Khronos~\cite{schmid2024khronos}: objects are associated by
surface, must share the class, and match within 2\,m. It scores the current map and its history together.
\TODO{Report a 0.5\,m gate next to the 2\,m gate once the timelines are re-scored.}
\emph{Change F1} counts appearance and disappearance events. For reference surface samples $G$ and a predicted map $M$,
$r(G,M)$ is the fraction of samples within 10\,cm of predicted surface of the same class, and a state is represented
when $r \ge 0.5$. A moved object gives two events, its old state disappearing and its new state appearing. We report
changes within a run, which happen in view or out of view, and changes between runs.
\emph{Old-site residue} is the fraction of old object surface that remains where later measurements observe free space.
Lower is better.
\emph{Geometry} is the F1 at 5\,cm between surface samples of the map and the reference. The real reference is
reconstructed from each run's own RGB-D data and covers what that run observes, so it tests accuracy there. The
simulated reference is the complete scene mesh, including surfaces that the last run leaves unobserved, so it also
tests completeness. We score each backend on its own surface: the TSDF mesh,
the occupied cells, and a TSDF fused from depth rendered from the Gaussians~\cite{huang20242dgs}.
\emph{Rendering} of the Gaussian maps follows GaME's protocol~\cite{yugay2026game}: PSNR, MS-SSIM~\cite{wang2003msssim},
LPIPS~\cite{zhang2018lpips}, and depth L1 on every tenth frame of the last run, held out from mapping. \emph{Own time}
renders each frame with the map of its own timestamp, $\mathcal{M}(t_k)$.
A cell reads n/a when the method lacks the capability: Khronos relates no two runs, Panoptic Multi-TSDFs keeps no
timeline, and only Gaussian maps render.

\paragraph{Protocol.}
Simulated runs use ground-truth poses, and real runs use the rigid alignment above. All datasets and backends use
the same constants (\cref{sec:handoff}).
All runs use one NVIDIA RTX 5070 Ti (16\,GB) and an AMD Ryzen 7 9700X with 44\,GB of memory.

Our layer carries the object states across runs. With the TSDF backend, the online object F1 of the real runs B and C
reaches 99.7 and 98.4, against 91.5 and 83.8 for Khronos, which starts each run from an empty map
(\cref{tab:main_real}). In the simulated run B, it rises from 66.8 for
Khronos to 91.3 (\cref{tab:main_sim}).

The layer detects all three kinds of change on every backend. Within a run, all three backends detect every
change on the real room and reach F1 100 and 96.3 on the simulated runs A and B. Khronos reaches 66.7 in the real runs
B and C and GaME 66.7 in run B, and the compared methods reach 67.9 to 91.7 on the simulated runs. Between runs, the
TSDF and Gaussian backends detect 15 of the 16 changes from A to B and the occupancy backend all 16. Every backend
detects all 10 changes from B to C and 29 of the 32 on the simulated apartment. On these three transitions, Panoptic
Multi-TSDFs reaches change F1 64.0, 37.5, and 91.8, GaME 93.3, 94.7, and 81.5, and wavemap 93.3, 100, and 93.3.

Obsolete surfaces leave the map. With our layer, 0.9\% to 14.3\% of the old object surface remains at sites that
later runs observe as empty, against 57.1\% and 60.1\% for Panoptic Multi-TSDFs and 42.4\% and 61.1\% under GaME's
update. Wavemap clears old surfaces with its rays, but it loses accuracy on the revisits.

Where a run observes, the updated TSDF and Gaussian maps are as accurate as maps of that run alone. On the real room, the TSDF backend
reaches geometry F1 94.3, 96.0, and 95.3, against 91.0, 95.9, and 94.7 for Khronos, which maps each run alone, and the
Gaussian backend stays within 0.3 points of a Gaussian map rebuilt from scratch (\cref{tab:ablation_variants}). The
backends' own updates lose accuracy on the revisits: in B and C, GaME's update falls 5.0 and 4.5 points below the
rebuilt map, and wavemap's 7.5 and 6.8 points. Our occupancy backend stays above wavemap's update, at 92.0 and 91.6 against 88.9 and 89.0.

Where a run does not observe, the memory of earlier runs completes the map. Against the complete simulated scene, the
updated maps of run B reach geometry F1 98.5 (TSDF), 96.6 (Gaussians), and 94.9 (occupancy), against 83.6, 85.4, and
84.2 for maps of run B alone. The compared methods that carry a map reach 92.1 (Panoptic Multi-TSDFs), 92.0 (GaME),
and 91.2 (wavemap).

On the public Flat dataset, the difference also appears only after the scene has changed (\cref{tab:flat}). In the
first run, every method starts from an empty map, and the geometry F1 agrees within 0.2 points. In the second run, our

Our layer also improves the rendering of the Gaussian map (\cref{tab:rendering}). On held-out frames of the last run,
our final map renders 2.81\,dB better than GaME's update on the simulated apartment, 0.96\,dB better on the real
room, and 1.47\,dB better on Flat, and it is better on every metric. It renders the simulated run 1.54\,dB better than a map rebuilt from scratch
and matches that map on the real room (19.90 against 19.93\,dB). Because objects also change during the last run,
rendering each frame with our map of its own time raises PSNR further, to 26.54 and 20.41\,dB, and improves every
metric on both datasets. GaME keeps only its final map. The refinement that follows the last run lowers GaME's
geometry F1 on Flat and on the real room and keeps ours (\cref{sec:supp_refinement}).

Starting a later run from scratch keeps each map accurate but incomplete, and carrying the map over keeps it complete
but stale (\cref{tab:ablation_variants}). A carried-over occupancy map keeps 99.6\% of the old object surface, and its
real geometry F1 falls to 85.2 and 82.2. The backends' own updates sit between: GaME's update keeps 42.4\% and 61.1\%
of the old surface, and wavemap's update removes most of it but loses accuracy on the real revisits. With our layer,
every backend reaches its highest geometry F1 against the complete simulated scene, with 0.9\% to 14.3\% of the old
surface left. Within the Gaussian backend, letting the layer choose the training keyframes instead of every stored
keyframe raises the geometry F1 of real run B by 3.1 points, and limiting pruning to the current run keeps 681{,}011
earlier Gaussians that GaME's pruning deletes (\cref{sec:supp_gaussian}).

backend maps real run B in 1{,}793\,s with a peak GPU memory of 7.2\,GB.
