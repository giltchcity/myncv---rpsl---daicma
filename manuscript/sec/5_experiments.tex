\section{Experiments}
\label{sec:experiments}

Our experiments separate two questions. First, can a dynamic mapper still model
motion and hidden changes during one run? Second, can the scene state from one
completed run be loaded into a later revisit and updated correctly? Khronos
provides the single-run dynamic-mapping baseline, Panoptic Multi-TSDFs provides
the repeated-visit mapping baseline, and our from-scratch variant removes only
the cross-run memory from our system.

\paragraph{Repeated real-room runs.}
We record the same room three times with an RGB-D camera. Run A lasts 133\,s;
run B lasts 135\,s and is recorded about six hours later; run C lasts 241\,s
and is recorded about twelve days after B. A starts from an empty map, B loads
the state exported by A, and C loads the state exported by B. A rigid transform
aligns B and C to the coordinate frame of A. Persistent instance IDs are
provided across the three runs.

The data contain 20 physical object identities. Hidden within-run changes
produce five evaluated state-change events: one in A, two in B, and two in C.
Between A and B, seven moved objects, one newly added object, and one removed
object produce 16 appearance/disappearance events. Between B and C, four moved
objects and two removed objects produce 10 events. Object reference surfaces are
aggregated from the RGB-D measurements during manually annotated presence
intervals.

\paragraph{Controlled synthetic runs.}
Two Isaac Sim runs observe the same furnished apartment. A contains 4,186 frames
and B contains 4,041 frames at 30\,Hz. Both use ground-truth camera poses,
semantics, and instance IDs. Run B loads the final state from A. The evaluated
within-run hidden changes contain 24 events in A and 10 in B; the A-to-B revisit
contains 32 evaluated appearance/disappearance events. The simulator also
provides the complete scene mesh, allowing geometry retained from the previous
run to receive credit even when B does not re-observe it.

\paragraph{Public sequences.}
For 3RScan~\cite{wald2019rio}, we use a reference scan as the first run and load
its map for the rescan. The current evaluation contains three reference/rescan
pairs: an unchanged case, a case with moved and removed chairs, and a third
changing scene. Khronos is run on the rescan from scratch. Bonn RGB-D
Dynamic~\cite{palazzolo2019bonn} and TUM~\cite{sturm2012tum} contain only one
visit, so no previous map is loaded; they check the single-run behavior of our
dynamic-mapping pipeline.

\subsection{Metrics}
\label{sec:protocols}

\paragraph{Online object reconstruction.}
We use the Khronos object evaluator. Predicted and reference objects of the same
semantic class are associated by surface distance with the published 2\,m gate.
Object precision, recall, and F1 are evaluated over time and weighted by state
duration. This metric measures the quality of the online object map during one
run.

\paragraph{Object-state changes.}
For an annotated object-state surface $G$ and predicted map $M$, define
\begin{equation}
 r(G,M)=\frac{|\{x\in G:d(x,M_{\ell(G)})\le0.10\,\mathrm{m}\}|}{|G|},
 \label{eq:representedness}
\end{equation}
where $M_{\ell(G)}$ is predicted surface with the semantic class of $G$. A state
is represented when $r(G,M)\ge0.5$. A moved object contributes two events:
disappearance of the old state and appearance of the new state. A removed
object contributes one disappearance; a newly added object contributes one
appearance. Precision, recall, and F1 are computed over these events.

We use the same state definition for hidden changes discovered after an
observation gap within a run and for changes between two runs. \emph{Old-location
residue} measures the fraction of an old object surface that is still present
after later sensor observations have confirmed that location to be empty.

\paragraph{Scene geometry.}
Geometry precision measures how much predicted surface is supported by the
reference; recall measures how much reference surface is reconstructed. For the
synthetic apartment the reference is the complete simulator mesh. For the real
room the reference is reconstructed from each run's own RGB-D measurements, so
we report geometry inside the region observed by that run. All geometry results
below use a 5\,cm distance threshold.

With exact ground truth, our method detects all 24 hidden changes in A and all

therefore almost entirely coverage rather than a precision trade-off.

The two references expose different aspects of the map. In simulation, the
complete reference includes surfaces remembered from A even when B does not see
them again, so loading memory raises recall by almost 20 percentage points while
precision stays unchanged. In the real room, each reference is reconstructed
from the current run itself; surfaces remembered only from an earlier run do not
increase recall. Recall therefore changes little, while precision drops by
5--6 points even inside the currently observed region. The dominant visible
failure is duplicate background geometry: a single rigid alignment does not
remove all residual misalignment, so old and newly reconstructed walls can form
two nearby surfaces.

Bonn and TUM test only single-run behavior. In Bonn's placing sequence, the final

the observed 0.75\,m motion is below Khronos's 1\,m displacement threshold. On
TUM \emph{walking\_xyz}, person contamination is 1.02\% for our method and
1.09\% for Khronos.
