## Canonical Storyline Correction

The project must not describe D1, D2, and D3 as three parallel dynamic regimes.
The authoritative hierarchy is:

```text
D1 + D2 = dynamic mapping inside each continuously running session
D3      = persistent scene-memory continuation across completed sessions
```

- D1 is continuously observed motion inside a session.
- D2 is hidden change during an observation gap in the same still-running
  session.
- D3 is the inter-session boundary: Session B imports memory from completed
  Session A, reconciles A-to-B changes, and concurrently runs new D1 and D2.

The Introduction, Related Work, storyline, README, and agent handoff were
rewritten to follow this hierarchy. The authoritative re-audit is
`08_STORYLINE_TAXONOMY_REAUDIT_2026-08-06.md`.

## Latest Technical Progress Carried Forward

### 1. Single-session D1 support

Configured dynamic semantic pixels are masked from static TSDF integration and
can be promoted into Khronos's existing active-window tracker. The controlled
Human track increases from 114 to 170 samples and extends from 11.62 s to
14.52 s. A 138-vertex human-scale static residual present in the geometric-only
run is absent after semantic masking.

### 2. Single-session D2 base

Khronos already supplies the active/global machinery for changes that occur
while the same session remains active but the robot is looking elsewhere. The
final paper must evaluate D2 using a continuous causal sequence, not infer D2
from a process-separated A/B experiment.

### 3. Cross-session D3 global-map continuation works at reconciliation level

Session B reconciliation starts from Session A's saved global mesh. B geometry
is evidence and update material, rather than replacing A with a fresh map.

The method retains unobserved A geometry, deletes ray-confirmed absent A
geometry, and welds genuinely new B geometry into the retained topology.

This result is reconciliation-level continuation, not a native hot restart of
the full Khronos backend.

### 4. Object-near structural deletion fixed

The previous cleanup could remove wall/floor vertices merely because they were
near an object private mesh or expanded bbox. The new B-only re-observation gate
protects:

- vertices supported by current B surfaces;
- vertices with ray presence evidence;
- vertices with no reliable re-observation.

Removal is allowed only for ray-confirmed absence.

Controlled B03 result:

```text
old object cleanup removed:          2939
new current-surface protected:       2938
new unobserved protected:               1
separate prior ray-confirmed absent: 2786
current B vertices added:            1981
```
